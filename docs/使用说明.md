# Arknights Painter 使用说明

Arknights Painter 用于把普通图片转换成 24×24 像素画，并通过 ADB 将每个格子的点击操作发送到安卓模拟器中的绘画页面。本文以 Windows 11 和横屏安卓模拟器为例，介绍从连接设备到完成绘制的完整流程。

> 本工具只负责输入画面，不会自动点击保存、发布或提交。使用前请确认目标软件允许使用自动化输入，并自行备份重要内容。

## 一、准备工作

### 1. 下载程序

从 [GitHub Releases](https://github.com/Dr-hydra/Arknights-Painter/releases/latest) 下载 `ArknightsPainter.App.exe`。这是 win-x64 .NET 10 自包含单文件，通常不需要另外安装 .NET 运行时。

程序不包含 Android Platform Tools。请准备模拟器自带的 `adb.exe`，或安装 Android Platform Tools。当前版本支持 64 位 Windows 10 19041 及以上系统，推荐使用 Windows 11。

### 2. 准备模拟器画面

1. 启动安卓模拟器，并确认 ADB 调试已开启且已经授权。
2. 进入目标软件的横屏 24×24 绘画页面。
3. 保持画板和颜料面板可见，不要打开键盘、通知栏或其他遮挡层。
4. 绘制期间不要切换页面、滚动画面或改变模拟器分辨率。

## 二、连接 ADB 设备

1. 启动 `ArknightsPainter.App.exe`。
2. 在右侧“ADB 设备”区域点击刷新按钮。
3. 如果程序提示找不到 `adb.exe`，在“ADB 路径”中填写完整路径，例如：

   ```text
   C:\Program Files\Netease\MuMuPlayer-12.0\shell\adb.exe
   ```

   程序会优先检查已填写的路径，也会自动检查 MuMu、雷电、蓝叠、Android SDK 和系统 PATH。
4. 如果模拟器使用 TCP 连接，在“TCP 端点”中填写模拟器地址，默认值为 `127.0.0.1:16384`，然后点击“连接”。
5. 在设备列表中选择状态为 `device` 的设备。

只有设备在线时才能进行截图、校准和绘制。常见状态含义如下：

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| `device` | 已在线并可操作 | 可以继续 |
| `offline` | ADB 连接未完成 | 重启 ADB 或重新连接模拟器 |
| `unauthorized` | 未授权当前电脑 | 在模拟器中确认 USB/ADB 授权提示 |
| 未发现设备 | 路径或连接不正确 | 检查 ADB 路径、端点和模拟器设置 |

## 三、导入图片并转换

### 1. 导入和裁切

支持 PNG、JPEG、BMP 和 WebP。可以点击“打开图片”选择文件，也可以把图片拖入左侧导入区域。导入后，中间会显示 24×24 预览和颜色统计。

如果图片主体周围有水印或多余内容，点击图片区域旁的裁切按钮，在裁切窗口中调整范围并保存。裁切窗口显示的是导入图片本身；画面校准窗口显示的则是之后从模拟器获取的实时截图，两者不要混淆。

### 2. 选择构图方式

- **完整适配**：保持原图比例，完整内容缩放到 24×24，空白区域使用背景色填充。适合不希望裁掉主体的图片。
- **居中裁切**：保持比例铺满画布，超出部分从四周裁掉。适合主体位于图片中央的方形构图。
- **直接拉伸**：不保持比例，直接拉伸到 24×24。适合原图比例接近目标画布的情况。

### 3. 选择转换算法

- **拼豆均色**：对每个目标格进行面积采样后量化，照片、插画和渐变图片通常更自然。
- **拼豆主色**：更重视格子内出现频率最高的颜色，适合 Logo、图标和已有像素画，轮廓更明确。
- **感知平滑**：使用感知色差进行平滑映射，适合希望减少突兀色块、保留整体色调的图片。

### 4. 设置背景和抖动

“留白颜色”只影响完整适配时的空白区域，也会纳入 576 个格子的绘制，因此可以覆盖画布上原有内容。

抖动默认关闭。需要表现细微渐变时，可以尝试：

- **Atkinson**：纹理较轻，适合人物和插画。
- **Floyd-Steinberg**：细节和颗粒感更明显，适合照片或复杂渐变。
- **Bayer 4×4**：规律性较强，适合复古像素风格。

每次修改构图、算法、背景或抖动方式后，程序会重新生成预览。开始绘制前请检查主体位置、背景颜色和颜色统计是否符合预期。

## 四、画面校准

### 1. 自动识别

1. 确认模拟器仍停留在目标绘画页面。
2. 点击右侧“自动识别”。
3. 程序会通过 ADB 获取模拟器的**实时截图**，利用画板四角定位线、左右中点十字定位点、外框和 24×24 网格识别画布；颜料区域会根据当前页面布局定位。
4. 识别成功后，右侧会显示屏幕分辨率和校准置信度。

首次使用或更换模拟器分辨率时建议重新校准。校准结果按设备序列号和截图分辨率保存到：

```text
%LOCALAPPDATA%\ArknightsPainter\settings.json
```

### 2. 手动调整

自动识别失败时，点击“手动调整”。窗口中的背景图来自当前设备的实时截图，不是导入的图片，也不会受到导入图片水印的影响。

窗口中有两个矩形：

- 蓝色“画布”框：覆盖完整的 24×24 画板区域，包括边界范围。
- 橙色“颜料”框：覆盖颜料面板的可视区域，包含滚动后需要识别的色块。

拖动矩形移动位置，拖动右下角方块调整大小。确认两个区域都完整覆盖后点击“保存校准”。如果只看到截图左半部分，可以先最大化窗口或缩小系统显示缩放，再重新打开手动校准；校准图本身仍是完整设备截图。

## 五、开始绘制

点击“开始绘制”前，程序必须同时满足以下条件：

- 已导入并成功转换图片；
- 已选择状态为 `device` 的在线设备；
- 已存在匹配当前设备序列号和分辨率的校准配置。

开始后程序会先再次截图验证画面结构和内置色板签名。验证通过后按颜料顺序分组绘制，每批最多点击 20 个格子，默认点击间隔约 50 毫秒。每种颜料完成后会截图抽样校验，发现漏画会自动重试一次；仍然失败时会停止绘制并在日志中报告位置。

- **暂停/继续**：暂停在当前批次完成后生效，不会丢失已经完成的格子。
- **取消**：立即停止后续操作，不会回滚已经绘制的格子。
- **运行日志**：展开底部“运行日志”查看 ADB、校准、选色和校验信息。

绘制过程中请让模拟器保持前台页面可见，不要手动点击画板或滚动颜料面板。完成后请在目标软件中自行检查结果，并按需要手动保存或发布。

## 六、推荐设置

| 图片类型 | 构图 | 算法 | 抖动 |
| --- | --- | --- | --- |
| 人物照片、风景照片 | 完整适配或居中裁切 | 拼豆均色 | Atkinson 或 Floyd-Steinberg |
| Logo、图标、表情 | 居中裁切 | 拼豆主色 | 无抖动 |
| 原有像素画 | 直接拉伸或完整适配 | 拼豆主色 | 无抖动 |
| 低对比度插画 | 完整适配 | 感知平滑 | Bayer 4×4 或无抖动 |

这些设置只是起点。最终效果取决于原图尺寸、透明区域、主体位置和目标软件当前色板，建议先观察 24×24 预览，再开始绘制。

## 七、常见问题

### 程序无法启动

优先下载 Releases 中的单文件版本，并将程序放在有写入权限的普通目录。首次启动可能需要几秒钟解压 WinUI 原生组件；如果仍然退出，请确认系统为 64 位 Windows 10 19041 或 Windows 11。

### 找不到 ADB 或设备列表为空

确认 ADB 路径指向实际的 `adb.exe`，在 PowerShell 中运行 `adb devices` 检查设备是否出现。若使用 TCP 连接，先点击“连接”再刷新设备；同时连接多个设备时要在列表中明确选择目标设备。

### 自动识别失败

确认目标软件已经打开横屏绘画页面，并且画板四周的定位点没有被弹窗、通知栏或其他窗口遮挡。关闭遮挡后重新截图识别；仍失败时使用手动调整，并确保画布框和颜料框都完整覆盖目标区域。

### 开始绘制按钮不可用

检查是否已经导入图片、选择在线设备并完成当前分辨率的校准。更换模拟器分辨率、窗口方向或设备序列号后，需要重新校准。

### 绘制中途暂停或报画面不匹配

不要操作模拟器，先查看运行日志。程序检测到画板结构、色板签名或选中色块发光边框不符合预期时会主动停止，这是为了避免盲目点击。恢复正确页面后重新校准，再点击“开始绘制”。当前版本会重新绘制全部 576 格，以覆盖画板上的现有内容。

## 八、数据和隐私

程序只在本机保存 ADB 路径、TCP 端点和校准矩形，文件位置为 `%LOCALAPPDATA%\ArknightsPainter\settings.json`。导入图片不会上传到网络，ADB 命令只发送到你选择的本地模拟器设备。

项目源码和问题反馈请访问 [GitHub 仓库](https://github.com/Dr-hydra/Arknights-Painter)。
